## 0. 使用说明

本文件是“材料如何被生产、核验、更新和面向不同受众复用”的母版，不替代顶层设计、正式 PRD、白皮书、招商材料、演示讲稿或操作手册本身。

任何下游材料必须同时遵守：

1. C0 最新决策优先于领域提案、原 PRD 和历史材料。
2. 原 PRD 是战略与能力蓝图，不是当前交付承诺。
3. C1—C5 规格中的 `PROPOSED` 只有在 C0 会签明确吸收后，才能写作当前决策。
4. “D1 暂定冻结”表示获准用于 Demo 设计，不自动表示代码已实现或已验收。
5. 商业 MVP 尚未启动；真实售价、资金结算、部署形态、授权和 SLA 均不得对外承诺。
6. Demo 数据可以 Mock，但必须标明“演示数据”，且不得与真实报价、真实余额或真实客户事实混用。

- 老板材料先讲决策和风险，不展示未经批准的数据模型细节。

## 3. 原始 PRD 提取

### 3.1 原始定位、目标与范围

原 PRD 将产品定义为面向本地生活探店获客、老板个人 IP 和电商广告素材的全链路智能生产平台，核心判断是：产品不是单一“文生视频按钮”，而是可复用、可追溯、可审批、可学习的营销生产系统，最终追求到店、留资、成交与账号资产增长。该判断属于原始战略输入；当前项目章程进一步将商业核心冻结为“销售 AI 视频额度，以场景 Agent 包装能力，以 StoryCanvas 完成专业生产”。

原 PRD 的建议形态：

- Web SaaS。
- 移动端拍摄助手。
- 开放 API/工作流。
- “1 个共享智能生产底座 + 3 个垂直业务 Agent + 1 个增长闭环”。

原 PRD 的 12 个月目标包含以下数字，均为 `PROPOSED_FROM_ORIGINAL_PRD`，未被当前 C0 决策批准为进度或 SLA：

- 单条视频从需求录入到可审核初版的人工操作时长降至 15 分钟以内。
- 标准模板成片自动化覆盖率达到 80%。
- 支持三类业务的一致生产协议。
- 批量生成差异足够、变量和表现可追踪的多版本素材。
- 在发布前控制事实错误、越权克隆、违规宣传、版权不明和 AI 标识缺失。

### 3.2 原始非目标

- 首期不自研基础大模型、视频扩散模型、TTS 或数字人底模。
- 不保证“一键生成必爆款”。
- 未经授权不自动发布、不改投放预算、不克隆人脸或声音。
- 不用生成画面伪造到店体验、顾客评价、疗效、销量、价格等可验证事实。

这些非目标与当前冻结原则方向一致，可作为风险约束引用；具体实现和合规状态仍需当前证据。

### 3.5 原始风险

| 风险 | 原 PRD 缓解方向 | 当前材料口径 |
|---|---|---|
| 范围过大 | 模板剪辑、底模外购、按行业/平台收缩 | 已确认原 PRD 30 个 P0 过载；D1 收敛到基础生成 + 本地生活 |
| 内容同质化 | 相似度门禁、真实素材、人工抽检 | 当前为产品原则/后续能力，不宣称已完整实现 |
| 幻觉与虚假体验 | 事实库、Claim 引用、过期和高风险阻断 | D1 必须沿用统一事实与禁用规则；实现状态按证据标记 |
| 数字人滥用 | 实名、单独同意、范围授权、水印、撤销 | 数字人未进入 D1；正式售卖前需法务与授权 Gate |
| 供应商锁定 | 统一网关、基准集、双供应商、资产可迁移 | 当前 StoryCanvas 可信引用仍存在供应商耦合 |
| 成本失控 | 预算、配额、预览、缓存、熔断 | 当前冻结额度状态机；真实 meter、成本精度和规则未冻结 |
| 平台政策变化 | 连接器隔离、人工导出兜底、规则版本化 | D1 以导出为主，不承诺自动发布 |
| 增长误归因 | 最小有效差异、对照和归因窗口 | 经营数据回流与策略学习后置 |
| 版权争议 | 权利元数据、授权、相似性检查 | 当前权利证据和 AssetReceipt 仍需补齐 |

当前项目还增加了 Toonflow 商业授权/标识、FireRed 资源和接口、本地单用户架构、任务恢复、双轨数据、Demo 主数据冲突等风险。它们优先于原 PRD 的泛化风险表。

| 合同已实现 | 合同 fixture、双端解析证据、正负向验证 |
| 真实生成可用 | 任务 ID、供应商/模型、状态、资产、错误/成本字段和环境限制 |
| 商业可售 | C0/用户批准 + 法务/财务/授权 + 产品/SKU/价格/交付/支持政策 |
| 生产可用 | C7 Gate、权限/恢复/审计/监控/安全/备份证据 |

## 7. 版本更新机制

### 7.1 版本号

- `0.x`：材料体系和内容骨架提案，允许结构调整。
- `1.0`：C0 批准的首个正式内部材料基线。
- Major：受众、商业核心、产品边界或架构发生不兼容变化。
- Minor：新增已批准能力、阶段、材料类型或受众。
- Patch：不改变语义的文字、链接、格式和来源修正。

版本号不能代替状态标签。`v1.0 PROPOSED` 仍然不是批准材料。

### 7.2 触发更新的事件

- C0 更新共同记忆或发布新的会签/ADR。
- D1/MVP Gate 状态变化。
- Product/SKU/Entitlement、价格或商业政策获批。
- 公共集成合同变更。
- 当前实现或 C7 验收改变能力状态。
- 供应商、授权、法规、平台政策或部署边界变化。
- 对外反馈暴露事实错误或歧义。

### 7.3 更新流程

```text
变更触发
-> C8 建立变更单和受影响声明清单
-> 向事实 Owner 核验
-> 更新声明台账和来源
-> 修改母版材料
-> 执行差异审查（事实/数字/状态/术语/受众）
-> C0/专业 Owner 审批
-> 发布新版本并归档旧版
-> 通知下游材料 Owner 更新或停止使用
```

禁止静默覆盖已外发版本。旧版必须保留版本号、发布日期、适用 Gate 和“已废止/仍有效”状态。

### 7.4 变更影响分级

| 级别 | 示例 | 审批 |
|---|---|---|
| `L0` 文字修正 | 错别字、链接、格式 | C8 |
| `L1` 事实澄清 | 不改变决策的术语、状态或来源补充 | C8 + 事实 Owner |
| `L2` 范围/能力变化 | D1/MVP 范围、功能状态、工作台、合同语义 | C0 + Owner |
| `L3` 商业/法律变化 | 价格、分润、客户承诺、授权、隐私、税务、上线 | 用户/C0 + 法务/财务/相应 Owner |

### 7.5 材料头部最小元数据

每份正式材料必须包含：

```text
标题 / 材料类型 / 目标受众
版本 / 状态 / 适用 Gate
Owner / 审核人 / 批准人
发布日期 / 最近核验日 / 下次复核日
事实基线 / 实现证据版本
对外可用性 / 保密级别
已知限制 / 替代版本
```

## 8. 材料生产顺序

建议顺序：

1. 先由 C0 批准本材料体系和状态标签。
2. 以顶层设计作为所有材料的事实母版。
3. 在 C6 D1 体验路径和 C7 验收证据稳定后，形成正式 PRD 的 D1 版。
4. 从已批准顶层设计/PRD 派生老板讲稿和操作手册。
5. 产品白皮书和招商材料最后生成，并单独通过对外声明 Gate。

招商材料不能成为定义产品事实的上游；演示讲稿和操作手册也不能反向修改 PRD 或公共合同。
