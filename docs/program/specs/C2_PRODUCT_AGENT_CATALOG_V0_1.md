## 1. 结论摘要

首版不把原 PRD 的 30 个 P0 平铺为 30 个独立交付项，而是收敛为三层：

1. **共享生产能力**：Brief、品牌事实、脚本、分镜、素材、生成、编辑、审核和导出等可复用生产原语。
2. **场景 Agent**：本地生活、老板 IP、电商，把共享原语编排成客户能理解的业务流程。
3. **商业能力**：Product、SKU、Entitlement、项目授权和用量可见性，把生产能力变成可购买、可授权、可解释的商品。

产品组合采用“一个基础生产包 + 三个场景包 + 两个扩展包”：

- 基础生成包
- 本地生活 Agent 包
- 老板 IP Agent 包
- 电商素材 Agent 包
- 数字人扩展包
- API 扩展包

阶段收敛如下：

- **Demo**：只完整演示“基础生成 + 本地生活”，额度、任务和授权使用 Mock。
- **商业 MVP**：基础生成与本地生活可售；老板 IP 先提供真人素材模式试点；电商先提供受控小批量变体试点。
- **后续**：数字人、开放 API、自动发布、经营数据学习和大规模变体。

## 2. 产品原则与边界

### 2.1 产品原则

- 客户购买的是“AI 视频生产能力和额度”，不是上游 token 或具体模型。
- 场景 Agent 是流程模板和业务知识包装，不是独立租户，也不复制生产引擎。
- 同一能力只定义一次；场景 Agent 通过编排和参数约束复用。
- Demo 数据只使用 `demo-local-001`，不创建第二套海底捞主数据。
- 真实门店、人物和商品事实必须来自已确认的 Claim/Rule；AI 画面不能伪装为真实证据。
- 能力可见、可操作、可消费必须同时满足组织身份、成员角色、Entitlement 和数据范围。
- 供应商、模型和成本是内部实现；客户只看到能力、任务状态、额度变化原因和交付物。

### 2.2 本文不决定

- 真实售价、批发价、活动价、返点、佣金或分润。
- 额度换算、预冻结数值、扣减精度、失败补偿或账本实现。
- 上游供应商选择、模型路由和任务队列。
- Entitlement、Project Token 或回执的最终数据库/API Schema。
- 自动发布、支付、结算、生产部署或法务授权结论。

## 3. 三层产品模型

```text
商业能力层
  Product / SKU / Entitlement / Project Authorization / Usage Visibility
                             |
                             v
场景 Agent 层
  本地生活 Agent / 老板 IP Agent / 电商 Agent
                             |
                             v
共享生产能力层
  Brief → Context → Script → Storyboard → Asset/Generate
        → Timeline → QA → Export → Receipt
```

### 3.1 共享生产能力

以下 Capability Key 是 C2 的产品语义提案，不是已冻结接口字段。

| Capability Key | 能力 | 主要输入 | 标准输出 | 客户价值 | 阶段 |
|---|---|---|---|---|---|
| `production.brief` | 智能 Brief | 目标、受众、平台、时长、CTA、素材、限制 | 结构化 Brief、缺口清单 | 降低需求沟通成本 | Demo |
| `production.context` | 品牌/场景上下文 | Brand、Store、Claim、Rule、引用资产 | 版本化上下文快照 | 减少幻觉和品牌偏差 | Demo |
| `production.script` | 脚本生成与编辑 | Brief、上下文、Agent 模板 | 多版本结构化脚本、引用、风险 | 快速得到可审脚本 | Demo |
| `production.storyboard` | 分镜与生产计划 | 已批准脚本、比例、时长、素材约束 | Scene/Shot、拍摄/生成需求 | 把文案变成可执行生产单 | Demo |
| `production.asset-plan` | 素材匹配与缺口处理 | Shot、已有素材、引用规则 | matched/reshoot/missing/AI 备选 | 先复用真实素材，减少无效生成 | Demo |
| `production.image-generate` | 图片生成/改图 | Shot、提示词、引用、品牌规则 | 图片资产与任务回执 | 生成封面、图卡、背景和合规补镜 | 商业 MVP |
| `production.video-generate` | 视频生成 | Shot、参考图、运动与连续性要求 | 视频资产与任务回执 | 补充可控镜头和广告创意 | 商业 MVP |
| `production.voice` | TTS/配音 | 台词、声音配置、授权范围 | 音频资产与任务回执 | 降低重复录音成本 | 商业 MVP |
| `production.timeline` | 时间线与初剪 | Shot、资产、模板、字幕和音轨规则 | EditSession/TimelineVersion/预览 | 从素材快速形成可编辑初剪 | Demo 跳转；MVP 真实 |
| `production.qa` | 业务与成片 QA | 脚本、素材、时间线、规则 | 风险项、阻断项、修复建议 | 在交付前发现事实和视听问题 | Demo 基础；MVP 强化 |
| `production.export` | 导出交付 | 已通过 QA 的时间线、平台预设 | ExportArtifact、交付状态 | 得到可发布成片 | Demo 预览；MVP 真实 |
| `production.variant` | 受控变体 | 母版、变量矩阵、差异规则、上限 | 带 `creative_id` 的变体组 | 提升素材测试效率 | 电商试点/后续 |
| `production.digital-human` | 数字人合成 | 授权、人物/声音资产、脚本、场景 | 合成片段、授权校验与回执 | 减少固定口播的拍摄负担 | 后续 |
| `production.metrics` | 结果数据回流 | `creative_id`、平台/业务指标 | 归因记录、下一轮建议 | 从出片走向可学习增长 | 后续 |

### 3.2 场景 Agent

| AgentTemplate | 核心工作 | 场景特有约束 | 复用的共享能力 |
|---|---|---|---|
| 本地生活 Agent | 门店事实 → 到店策略 → 脚本 → 证据镜头 → 成片 | 地址、营业时间、价格、套餐、POI、活动有效期；真实门店素材优先 | Brief、Context、Script、Storyboard、Asset Plan、Timeline、QA、Export |
| 老板 IP Agent | 人物档案 → 栏目/选题 → 可说脚本 → 真人或授权分身 → 系列内容 | 观点必须经本人确认；人设冲突复核；人脸/声音按用途和期限授权 | Brief、Context、Script、Storyboard、Voice、Timeline、QA、Export |
| 电商 Agent | 商品事实 → 创意变量 → 多版本脚本 → 受控变体 → 交付 | 卖点证据、价格/库存有效期、免责声明、变量最小有效差异 | Brief、Context、Script、Storyboard、Variant、Generate、QA、Export |

场景 Agent 只改变流程、模板、必填字段和验收规则，不直接操作钱包，也不绕过 Project/GenerationTask。

### 3.3 商业能力

| 商业能力 | C2 定义的产品语义 | 实现/决策 Owner |
|---|---|---|
| 产品目录 | 客户能理解的产品名称、适用场景、包含能力和价值 | C2 主提案，C0 批准 |
| SKU 规格 | 产品的可购买规格，表达有效期、额度包、席位/并发/调用边界等商业维度 | C3 主责计价；C2 提供产品组合 |
| Entitlement | 某组织在某时间和范围内被授予的能力使用权 | C4 实现，C1/C3 会签语义 |
| 项目生产授权 | 把有效 Entitlement 收敛为某项目可用的 Capability 清单和期限；实现对象候选为 C4 提案的 `ProductionGrant` | C4/C5 合同，C0 批准 |
| 用量可见性 | 客户能看到任务为何冻结、消费或释放，但不看到上游成本与密钥 | C3/C4 |
| 渠道可售性 | 哪些 Product/SKU 可被某渠道采购、转售或分配 | C1/C3 |
| API 凭证 | 下游只获得受限 Platform API Key，不能获得上游供应商 Key | C4 |

## 4. 六个能力包

### 4.1 基础生成包

**定位**：所有场景产品的生产底座；单独购买时也能完成通用短视频项目。

**输入**

- 租户、品牌、项目与操作者上下文。
- Creative Brief：目标、受众、平台、比例、时长、CTA。
- 已确认事实、禁用词、品牌视觉/文案规则。
- 已有素材、引用资产与权利说明。
- 已购能力与项目授权。

**输出**

- 结构化脚本版本和引用关系。
- Scene/Shot 与素材需求。
- ProjectProductionPackage。
- GenerationTask/Asset 回执。
- TimelineVersion、QA 结果和 ExportArtifact。

**客户价值**

- 用一套可追溯流程替代“多个 AI 单点工具 + 人工搬运”。
- 场景包可共享资产、规则和生产引擎，避免重复采购和重复学习。

**阶段**

- Demo：Brief、品牌上下文、脚本、分镜入口、素材状态、StoryCanvas 跳转、Mock 任务/额度、导出预览。
- 商业 MVP：真实项目授权、可计量生成、资产回执、基础 QA 和真实导出。
- 后续：供应商智能路由、复杂剪辑、更多格式和高级协作。

### 4.2 本地生活 Agent 包

**定位**：面向餐饮、美业等门店，把真实经营事实和实拍素材包装为到店/团购内容。

**输入**

- Brand、Store、地址/商圈、营业时间。
- 套餐、价格、招牌服务、活动有效期和来源。
- 到店/团购/私信等目标、平台、受众和 CTA。
- 门店实拍素材、不可拍区域和风险规则。

**输出**

- 资料缺口和事实确认清单。
- 探店体验、套餐拆解、攻略等策略角度。
- 多版本脚本、证据镜头、门店拍摄/补拍清单。
- 同城/团购/老板出镜等合规变体。
- 成片、任务/资产回执和使用明细入口。

**客户价值**

- 减少代运营访谈、写稿和反复补拍。
- 把地址、价格、套餐和 CTA 的正确性前置到脚本和镜头。
- 让单店方法可复制到连锁门店，但保持每家门店事实独立。

**阶段**

- Demo：唯一黄金场景，必须端到端可讲。
- 商业 MVP：首个正式可售场景包。
- 后续：移动拍摄助手、POI/团购连接、同城经营数据回流。

### 4.3 老板 IP Agent 包

**定位**：围绕经本人确认的人设、观点和案例，持续生产一致的老板内容。

**输入**

- 人物简介、经历、价值观、专业领域、代表案例。
- 已确认观点、禁区、口头禅、表达节奏和栏目体系。
- 真人素材、B-roll；如使用声音/数字分身则附独立授权。
- 内容目标、目标受众、平台、时长和 CTA。

**输出**

- 栏目/选题建议和重复度提示。
- 观点、故事、案例、问答等可说脚本。
- 提词器稿、分镜/B-roll 清单、真人模式初剪。
- 经授权时的数字人/声音合成任务。
- 人设冲突、未确认观点和授权风险提示。

**客户价值**

- 维持长期人设与观点一致，降低每周策划和录制压力。
- 允许真人拍摄与授权分身双轨，而不是默认克隆。

**阶段**

- Demo：展示产品卡和输入/输出说明，不进入黄金路径。
- 商业 MVP：真人素材 + 提词器/脚本/初剪的邀请制试点。
- 后续：经法务和授权机制确认后接数字人；再增加栏目运营和表现学习。

### 4.4 电商素材 Agent 包

**定位**：把商品事实、卖点证据和实验变量转成可追踪的广告素材。

**输入**

- 商品/SKU、价格、库存、规格、卖点及证据。
- 目标受众、渠道、投放目标、优惠和 CTA。
- 商品图片/视频、真人或已授权数字人素材。
- 允许变化的钩子、卖点顺序、场景、时长和 CTA。

**输出**

- 创意变量矩阵和预算内组合建议。
- 问题-解决、测评、开箱、FAQ、促销等结构化脚本。
- 带 `creative_id` 与变量标签的受控变体。
- 商品镜头、卖点卡、免责声明和交付资产。
- 后续可接指标回流与下一轮建议。

**客户价值**

- 提升创意测试吞吐量，同时保留每条素材的变量和证据链。
- 避免“12 条素材只换字幕颜色”的无效批量。

**阶段**

- Demo：展示产品卡和样例矩阵，不承诺真实批量生成。
- 商业 MVP：单商品、小批量、人工审批的试点；不接自动投放。
- 后续：批量渲染、指标导入、归因、策略学习和商品系统连接。

### 4.5 数字人扩展包

**定位**：供老板 IP 或电商场景选配的受控人物/声音合成能力，不作为默认生产方式。

**输入**

- 授权主体、用途、平台、有效期、撤销状态和证据。
- 人物/声音资产 ID、脚本、语言、情绪、场景和输出规格。
- 项目授权与所需基础/场景包 Entitlement。

**输出**

- 授权校验结果。
- 口播音频或数字人片段。
- AI 标识、任务回执、模型/资产链路和审核状态。
- 授权无效时的标准化拒绝原因。

**客户价值**

- 降低固定口播和多版本本地化的重复拍摄成本。
- 通过用途/期限/平台限制降低冒用风险。

**阶段**

- Demo：只展示“未购买/待授权”状态和价值说明，不生成。
- 商业 MVP：不列为基础必需；最多封闭试点。
- 后续：在授权、删除、供应商和合规 Gate 通过后正式售卖。

### 4.6 API 扩展包

**定位**：让企业系统或合作伙伴以受限平台凭证创建项目、查询任务和接收回执。

**输入**

- Platform API Key、tenant/project 上下文和幂等键。
- 结构化 Brief、资产引用、Capability 请求。
- Webhook 地址与事件订阅。

**输出**

- 项目/任务标识、状态、标准化错误。
- GenerationTaskReceipt、AssetReceipt、ExportArtifact 引用。
- Webhook 事件和额度消耗摘要。

**客户价值**

- 把平台嵌入客户现有 CRM、商品、内容或工作流系统。
- 对外保持稳定平台合同，隔离上游供应商差异和密钥。

**阶段**

- Demo：不开放真实凭证，仅展示产品说明。
- 商业 MVP：非首发必需；仅在有明确锚定客户时提供受限试点。
- 后续：开发者控制台、轮换/禁用、Webhook、日志、限流和正式 SLA。

## 5. Product / Capability / SKU / Entitlement 关系提案

### 5.1 定义

| 对象 | 权威含义 | 不应承担 |
|---|---|---|
| Capability | 可独立授权、校验或计量的原子能力，如 `production.script` | 页面菜单、模型名称、价格 |
| Product | 面向客户的价值包装，组合场景 Agent、Capability、服务说明和适用对象 | 购买实例、余额 |
| SKU | Product 的可购买规格；声明版本、有效期、授权范围和额度/席位等商业参数 | 上游供应商和成本算法 |
| Entitlement | 某组织实际获得的 Capability 使用权，带来源、范围、状态和有效期 | 钱包余额、历史账本 |

### 5.2 关系

```text
Product 1 ── N SKU
Product N ── N Capability
AgentTemplate N ── N Capability
SKU 1 ── N EntitlementGrantRule
Order/ManualGrant/Contract ──> Entitlement
Organization 1 ── N Entitlement
Entitlement ──> Capability + scope + limits + validity
EffectiveProjectCapabilities = 当前项目所需 Capability ∩ 组织有效 Entitlement
```

### 5.3 运行语义

1. 客户看到并选择 Product。
2. 下单或授权动作指向具体 SKU。
3. 商业系统依据已批准规则产生 Entitlement；本文不定义账本或价格算法。
4. 用户选择场景 Agent 创建 Project。
5. 控制平面校验角色、数据范围和 Entitlement。
6. 控制平面向生产平面签发只含项目、能力和有效期的 `ProductionGrant`/短期授权；最终对象名由 C4/C5 提案、C0 批准。
7. StoryCanvas 只执行被授权的能力并回传用量事实，不读取客户价格。

### 5.4 组合约束

- 本地生活、老板 IP、电商 Product 都依赖基础生成 Capability。
- 数字人是 Add-on，必须同时满足场景包、数字人 Capability 和有效授权。
- API 是访问渠道 Add-on，不自动授予数字人、视频生成或其他生产能力。
- 菜单可见不等于可使用；未购买、额度不足、授权过期和角色不足必须分别解释。
- SKU 可改变额度、期限、席位、并发、服务等级等规格，但不能改变 Capability 的业务含义。

### 5.5 产品包矩阵

| Product 提案 | 包含的核心能力 | 依赖 | Demo | 商业 MVP | 后续 |
|---|---|---|---|---|---|
| AI 视频基础生成 | Brief、Context、Script、Storyboard、Asset Plan、Timeline、QA、Export | 无 | 可演示 | 可售 | 持续增强 |
| 本地生活 Agent | 本地生活模板、事实字段、门店镜头与 CTA 规则 | 基础生成 | 黄金路径 | 首发可售 | 拍摄助手/经营连接 |
| 老板 IP Agent | 人物记忆、栏目、可说脚本、人设冲突检查 | 基础生成 | 说明卡 | 真人模式试点 | 数字人/学习 |
| 电商素材 Agent | 商品事实、变量矩阵、`creative_id`、受控变体 | 基础生成 | 说明卡 | 小批量试点 | 归因/策略学习 |
| 数字人 Add-on | Voice、Digital Human、授权校验和 AI 标识 | 基础生成 + 场景包 | 禁用态 | 封闭试点 | 正式可售 |
| API Add-on | Platform Key、异步任务、Webhook、回执 | 至少一个生产 Product | 说明卡 | 锚定客户试点 | 开发者平台 |

## 6. Demo、商业 MVP 与后续能力

### 6.1 Demo 必需

- 四工作台入口可解释：平台、渠道、企业、媒体生产。
- 企业客户可看到已购“基础生成 + 本地生活”以及模拟剩余额度。
- 从 `demo-local-001` 进入本地生活 Agent，不复制项目数据。
- Brief → 品牌事实/规则 → 脚本 → 分镜生产单 → StoryCanvas → 任务/资产回执 → 模拟额度变化 → 导出预览。
- 数字人/API/老板 IP/电商显示清晰阶段和禁用原因，不做伪功能。
- 对余额不足、未授权、事实过期、缺镜、生成失败和 QA 阻断提供可理解说明。

### 6.2 商业 MVP 必需

- 真实租户/组织上下文、角色和数据范围。
- Product/SKU/Entitlement 的最小可运行闭环。
- 基础生成与本地生活正式可售。
- 项目短期授权、任务预冻结/消费/释放和不可篡改流水由 C3/C4 实现。
- 真实 GenerationTaskReceipt、AssetReceipt、资产权利信息和基础 QA。
- 老板 IP 真人模式、电商小批量模式仅按试点开放。
- 明确人工审核点；导出优先，不以自动发布为前置。

### 6.3 后续能力

- 数字人和声音克隆正式商品化。
- 开放 API 开发者控制台与正式 SLA。
- 移动拍摄助手、自动发布、平台/CRM/POS 连接。
- 大规模批量变体、指标归因和策略学习。
- 海外本地化、模板市场和高级媒体生产。

### 6.4 从原 PRD 暂不纳入首版的典型项

- 原生移动拍摄助手。
- 完整素材理解与自然语言检索。
- 数字分身/声音克隆正式能力。
- 自动发布、矩阵号和发布排期。
- 经营指标自动归因和策略学习。
- 完整供应商运营后台、生产级 NFR 和删除证明自动化。

这些能力保留在路线图，不因原 PRD 标记 P0 就自动进入当前 Demo 或商业 MVP。

## 7. 海底捞三里屯完整案例

### 7.1 案例上下文

| 字段 | 值 |
|---|---|
| Project | `demo-local-001` |
| 品牌/门店 | 海底捞火锅 / 北京三里屯门店 |
| 场景 Agent | 本地生活 Agent |
| 平台 | 抖音 |
| 比例/时长 | 9:16 / 30 秒 |
| 受众 | 18—30 岁，北京本地及旅游美食人群 |
| 主 CTA | 领取团购券 / 到店核销 |
| 已购产品（Demo） | 基础生成 + 本地生活 Agent |
| 关键事实 | C1—C8 统一事实；不得另造事实集 |

### 7.2 业务脚本

**步骤 1：进入企业工作台**

- 老板看到门店、项目、已购能力和模拟额度。
- 系统确认当前组织具有基础生成与本地生活 Entitlement。
- 若未购买，本地生活 Agent 显示价值说明和购买入口；不允许伪装为可运行。

**步骤 2：选择本地生活 Agent**

- 创建/打开 `demo-local-001`。
- Agent 加载门店、平台、受众、CTA 和素材状态。
- 输出资料完整度，明确缺失项而不是直接编造。

**步骤 3：品牌大脑确认**

- 读取统一 C1—C8 事实、禁用词、门店规则和素材引用。
- 地址、营业时间、价格、套餐和 CTA 必须引用已确认 Claim。
- 系统形成项目上下文快照，供后续脚本和生产包使用。

**步骤 4：生成并编辑脚本**

- 本地生活 Agent 产出服务体验向、会员权益向、夜景种草向三个版本。
- 演示默认选择“版本 A · 服务体验向”。
- 用户可局部编辑并保留 C1—C8 引用；确认后形成已批准 ScriptVersion。

**步骤 5：创建分镜生产单**

- 脚本被拆成 8 镜：外景、进店服务、锅底、毛肚、虾滑、环境、会员权益、夜景 CTA。
- 每镜包含时长、画面目的、台词/字幕、来源类型、风险和备选。
- 控制平面打包 ProjectProductionPackage，并签发短期项目授权。

**步骤 6：进入 StoryCanvas**

- 已匹配镜头使用现有真实门店素材。
- 镜头 05“虾滑制作”标记 `reshoot`，提供补拍任务。
- 镜头 07“会员权益”标记 `missing`，可选择补拍、合规图卡或移除；不得用虚假顾客画面代替证据。
- StoryCanvas 调整镜头、引用和连续性，不读取钱包或客户价格。

**步骤 7：生成/补齐与额度状态**

- 只有选择可计量生成时，控制平面先校验 Entitlement 并进入 `reserved`。
- 成功形成可交付资产后进入 `consumed`；失败或取消进入 `released`。
- Demo 只模拟状态和原因，不定义数值算法。
- 生产平面回传 GenerationTaskReceipt 和 AssetReceipt。

**步骤 8：初剪与 QA**

- 时间线组合画面、口播/BGM、字幕和 CTA。
- QA 检查事实引用、缺镜、字幕、声音、平台安全区、资产权利和 AI 标识。
- 存在阻断项时导出不可用，并指出具体镜头和处理建议。

**步骤 9：交付与解释**

- QA 通过后生成抖音 9:16 ExportArtifact。
- 企业工作台显示成片、项目状态、资产链路和模拟额度明细。
- 老板能解释：买了什么 → Agent 做了什么 → StoryCanvas 如何生产 → 为什么扣额度 → 交付了什么。

### 7.3 案例最终输出

- 1 个已确认 Brief。
- 1 份品牌事实/规则快照。
- 3 个脚本版本，1 个已批准版本。
- 8 镜生产单及素材缺口处理。
- 生成/资产回执和 TimelineVersion。
- 1 个通过 QA 的 9:16 成片导出物。
- 可解释的模拟额度变化和任务链路。

### 7.4 Demo 验收

- 10—15 分钟内走完且不切换到第二套数据。
- 每个关键动作有真实状态变化或明确标注为 Demo。
- 本地生活 Agent 的输入、产物和价值可被非技术老板复述。
- 未购买、额度不足、授权过期、缺镜、生成失败和 QA 失败均可解释。
- StoryCanvas 不出现租户、客户价格、钱包或上游密钥。

## 8. 业务验收口径

### 8.1 产品目录

- 每个 Product 都有目标客户、输入、输出、价值、依赖和阶段。
- Product 不直接引用上游供应商或模型作为卖点。
- Add-on 不隐式授予其依赖能力。

### 8.2 场景 Agent

- 同一 Agent 流程可以落到 Project、ScriptVersion、Shot、GenerationTask、MediaAsset 和 ExportArtifact。
- 场景约束能阻止事实编造、错误授权和无依据生成。
- 场景差异来自业务字段、模板、规则和验收，不是复制页面或生产引擎。

### 8.3 商业授权

- 能回答“客户买了哪个 Product/SKU、获得哪些 Capability、在哪个范围和时间有效”。
- Entitlement 与 Wallet/CreditLedger 分离。
- 生产平面只收到项目可用 Capability，不收到客户价格和上游密钥。

## 9. 风险与待决

- Product/SKU/Entitlement 语义需要 C3 会签，避免与额度和订单模型冲突。
- Entitlement 的主体、范围和项目授权映射需要 C1/C4 评审。
- StoryCanvas 对 Capability 的实际覆盖和缺口需要 C5 映射。
- Demo 中产品选择、未购买态和跨平面叙事需要 C6 验证。
- 数字人涉及生物识别、授权、撤销和 AI 标识，未完成法务/合规 Gate 前不得正式售卖。
- API 包只有在真实锚定客户出现时才应进入商业 MVP，避免为“技术完整”扩张。
