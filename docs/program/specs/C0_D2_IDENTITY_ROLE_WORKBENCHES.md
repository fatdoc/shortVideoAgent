# C0 D2 身份、角色与工作台规格

## 1. 文档定位

- 阶段：D2 身份与角色工作台
- 基线：SaaS `98b07e9`
- 目标：在现有 D1 老板 Demo 上补齐可讲解的登录、会话、路由保护、角色工作台与越权拒绝闭环。
- 交付属性：仅前端 + Mock 演示。
- 非目标：本轮不建设生产认证、真实用户中心、真实服务端 RBAC、真实租户隔离或正式结算权限。

本规格是 D2 的实施与验收依据。任何前端允许或拒绝结果都只代表 Demo 行为，不构成安全边界。

## 2. D2 范围

### 2.1 本轮必须完成

1. 四种演示身份可从统一登录界面进入系统。
2. 登录后生成可恢复、可退出、可过期的本地 Mock 会话。
3. 未登录访问受保护页面时跳转登录页，并保留安全的回跳目标。
4. 已登录用户默认进入与身份匹配的工作台。
5. 菜单、首页信息和关键操作按身份呈现差异。
6. 用户直接输入无权路由或执行无权操作时，系统明确拒绝并提供返回入口。
7. 页面能展示当前身份、所属组织、角色与工作台上下文。
8. 现有 D1 品牌大脑、脚本、分镜、生产交接和额度演示链路继续可用。

### 2.2 本轮明确不做

- 账号注册、短信或邮件验证码、找回密码、MFA、SSO。
- 密码哈希、真实 JWT/OAuth、服务端 Session、Refresh Token。
- 真实用户、组织、Membership 与权限数据库。
- 服务端 Policy Engine、行级权限、字段级权限与数据脱敏。
- 代理层级的真实授权继承、区域隔离、价格权限、分佣和提现审批。
- 真实审计日志、风控告警、设备管理、踢下线和并发会话控制。
- 将 LocalStorage、前端路由守卫或 Mock 数据包装为生产安全能力。

## 3. 四身份模型

| 演示身份 | 组织上下文 | 默认工作台 | 核心演示职责 | 禁止跨越 |
|---|---|---|---|---|
| 平台管理员 | Platform | 平台管理工作台 | 租户与渠道总览、额度运营、平台风险与审计入口 | 不以企业成员身份编辑企业内容 |
| 渠道代理 | Channel level-1 | 渠道代理工作台 | 客户与下级渠道概览、额度分发、订单与收益演示 | 不进入平台治理页，不直接编辑客户品牌事实 |
| 企业管理员 | Enterprise Tenant | 企业经营工作台 | 品牌大脑、套餐、事实/证据/规则、团队与额度使用 | 不进入平台和其他租户数据 |
| 内容运营 | Enterprise Tenant / Production role | 内容生产工作台 | 案例识别、脚本、分镜、画布交接、任务与回执 | 不管理渠道、价格政策或企业高权限设置 |

说明：

- “内容运营”是企业租户内的生产角色，不是第四类 Tenant 或 Organization。
- 渠道层级在 D2 只用固定 Mock 身份表达一级代理视角；总代理、二级代理和继承规则留给后续后端 RBAC。
- 同一自然人多组织、多 Membership、多角色切换不在本轮做真实建模。

## 4. 登录与会话

### 4.1 登录页

登录页应支持老板演示快速进入，不制造“已接真实认证”的错觉：

- 展示产品品牌、Demo 环境标识与简短价值说明。
- 提供四张身份体验卡，清楚写明角色、组织和将进入的工作台。
- 支持选择身份并登录；可保留演示账号字段，但不得暗示真实账号已开通。
- 明示“演示环境 / Mock 身份 / 不连接生产用户系统”。
- 登录失败、会话失效和越权拒绝使用可理解的业务文案。

### 4.2 Mock 会话最小字段

```ts
type DemoSession = {
  version: 1
  sessionId: string
  identityId: string
  role: 'platform_admin' | 'channel_agent' | 'enterprise_admin' | 'content_operator'
  organizationId: string
  organizationType: 'platform' | 'channel' | 'enterprise'
  defaultWorkbench: 'platform' | 'channel' | 'enterprise' | 'production'
  issuedAt: string
  expiresAt: string
}
```

### 4.3 会话行为

- 登录成功：写入本地会话并进入默认工作台。
- 页面刷新：恢复未过期会话。
- 主动退出：清除会话并返回登录页。
- 会话缺失、损坏或过期：清除无效数据，跳转登录页。
- 回跳参数：只允许站内白名单路径，禁止外部 URL 和开放重定向。
- 切换身份：必须形成新的 Mock 会话，不复用上一身份的工作台状态。

## 5. 路由与权限矩阵

| 路由域 | 平台管理员 | 渠道代理 | 企业管理员 | 内容运营 |
|---|---:|---:|---:|---:|
| 平台管理 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 渠道代理 | 拒绝 | 允许 | 拒绝 | 拒绝 |
| 企业经营 | 拒绝 | 拒绝 | 允许 | 限定只读或拒绝 |
| 内容生产 | 拒绝 | 拒绝 | 允许 | 允许 |
| 品牌大脑 | 拒绝 | 拒绝 | 允许 | 允许业务操作 |
| 身份/组织高权限设置 | 平台范围允许 | 渠道范围限定 | 本企业范围允许 | 拒绝 |

路由保护顺序：

1. 判断是否存在有效 Mock 会话。
2. 判断目标路由是否属于已知受保护域。
3. 根据角色与组织上下文判断是否允许访问。
4. 允许时渲染目标页面。
5. 未登录时进入登录页；已登录但无权时进入统一 `403` 拒绝页。

前端隐藏菜单不是权限控制。即使菜单不可见，直接输入 URL 也必须得到同样的拒绝结果。

## 6. 角色工作台差异

### 6.1 平台管理工作台

- 平台租户、渠道、企业客户与额度总览。
- 平台运营指标、异常风险、审计入口。
- 演示级客户或渠道查看入口。
- 不展示企业内容生产的日常编辑动作。

### 6.2 渠道代理工作台

- 所属渠道、客户数量、下级渠道与额度库存。
- 客户开通、额度分发、订单与收益的 Mock 状态。
- 清楚区分平台政策、渠道售价与客户消费。
- 不暴露平台全局治理和其他渠道数据。

### 6.3 企业经营工作台

- 海底捞三里屯业务上下文。
- 品牌大脑、商家资料、套餐、事实语料、禁用词、老板 IP、引用和风险。
- 团队、项目、额度余额与生产结果概览。
- 可进入内容生产链路，但不能进入平台或渠道管理。

### 6.4 内容生产工作台

- 案例识别结果、脚本、分镜、素材、画布交接、生产任务与回执。
- 使用企业已批准的事实、证据和规则，不自行修改高权限商业配置。
- 失败时可讲清额度预留、释放和结果状态。
- 不显示渠道利益、企业结算管理或平台治理菜单。

## 7. 越权拒绝

D2 至少覆盖以下演示情形：

- 未登录访问任意受保护工作台。
- 渠道代理直接访问平台管理 URL。
- 内容运营直接访问企业高权限设置 URL。
- 企业管理员尝试进入其他租户上下文。
- 篡改或损坏本地会话。
- 使用过期会话继续访问页面。

统一拒绝页至少包含：

- `403` 或明确的“无权访问”状态。
- 当前身份和目标区域的简短说明。
- 返回当前角色工作台按钮。
- 退出并切换身份按钮。
- “前端 Demo 拒绝，不代表生产安全控制”的环境标识。

## 8. 演示主流程

1. 打开系统，未登录时进入统一登录页。
2. 选择“平台管理员”，登录并进入平台管理工作台。
3. 退出，选择“渠道代理”，展示渠道客户、额度和收益视角。
4. 退出，选择“企业管理员”，进入海底捞三里屯企业经营工作台。
5. 打开品牌大脑，讲解事实、证据、规则和风险如何约束生产。
6. 切换为“内容运营”，进入内容生产工作台并完成 D1 生产演示。
7. 手动输入一个无权路由，展示统一 `403` 拒绝。
8. 返回当前角色工作台，退出登录，闭环结束。

## 9. D2 验收清单

### 9.1 P0 必须通过

- [ ] 四身份均可从统一登录页成功进入各自默认工作台。
- [ ] 未登录直接访问四类受保护路由均被拦截。
- [ ] 四身份的默认工作台、菜单和首页内容存在可见差异。
- [ ] 直接输入无权 URL 得到明确拒绝，而不是空白页、崩溃或静默跳转。
- [ ] 企业租户上下文固定且不可通过前端参数进入其他租户。
- [ ] 刷新可恢复有效会话，退出后受保护页面不可继续访问。
- [ ] 会话损坏或过期后回到登录页。
- [ ] D1 品牌大脑到 StoryCanvas 的核心 Demo 链路无阻断。
- [ ] 所有页面明确标识 Demo/Mock，不宣称生产认证或生产 RBAC。

### 9.2 P1 应通过

- [ ] 登录页在 `1672×941` 和 `1440×900` 下无横向裁切。
- [ ] 工作台在 `1440×900` 下关键入口无需异常滚动即可讲解。
- [ ] 登录、退出、过期、越权均有一致的反馈文案。
- [ ] 安全回跳仅接受站内白名单路径。
- [ ] 身份切换后不残留上一角色的菜单和敏感工作台状态。
- [ ] 四身份名称、组织、角色和当前工作台在界面中可辨认。

### 9.3 验收证据

- 定向组件/路由测试结果。
- lint、build 与治理检查结果。
- 四身份登录及默认落点截图。
- 至少三种越权拒绝截图或自动化证据。
- `1672×941` 与 `1440×900` 的登录页及关键工作台截图。
- D1 主链回归记录。

门禁口径：

- 任一 P0 未通过：`NO-GO`。
- P0 全通过、P1 有不阻断演示的问题：记录风险后由 C0 决定条件 `GO`。
- 只有证据齐全才能宣称 `D2 DEMO GO`，不得写成生产可用。

## 10. 后续真实后端与 RBAC 边界

D2 后续进入生产化时，必须另立范围完成：

1. 真实 Identity Provider、密码/验证码/MFA/SSO 与账号生命周期。
2. 服务端签发、轮换、吊销和过期控制的安全会话。
3. User、Organization、Tenant、Membership、Role、Permission 的数据库模型。
4. 平台、渠道层级、企业租户和项目的数据隔离。
5. 所有 API 的服务端授权，拒绝只依赖前端路由或菜单。
6. 代理授权继承、价格可见范围、额度分配、分佣、提现和审批权限。
7. 审计日志、敏感操作二次确认、风控、告警与最小权限。
8. 数据库行级/字段级策略、越权渗透测试和安全评审。
9. 多组织、多角色切换及冲突策略。
10. 登录、权限和结算的生产监控、灾备及合规要求。

在上述能力通过独立安全验收前，D2 产物只能用于本地或受控内部演示。
