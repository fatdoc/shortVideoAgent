# AUTONOMY PROTOCOL · C0 自主调度授权

## 生效条件

本协议在用户明确发出“启动项目”“开始执行”或同等正式启动指令后生效。在正式启动前，C0 只维护顶层设计，不自行创建数字员工窗口。

## C0 获得的授权

协议生效后，C0 可以在已批准的 C0—C8 体系内自主：

- 创建、启动、暂停和继续数字员工窗口。
- 决定并行数量、启动顺序和任务拆分。
- 向员工发送补充任务、澄清和纠偏。
- 等待员工进度并处理非关键阻塞。
- 审核 HANDOFF、Request 和交付证据。
- 安排返工、集成、测试和 Gate 验收。
- 在现有范围内调整员工任务，不需要用户逐项确认。

所有新窗口必须使用：

- 模型：`gpt-5.6-sol`
- 推理强度：`high`
- 运行速度：`1.5x`

## 默认调度策略

- 第一批：C1、C2、C3、C4、C5。
- 第二批：在第一批形成稳定输入后启动 C6、C7、C8。
- 同时活跃窗口默认不超过 5 个，避免公共合同和文件冲突。
- C0 根据依赖关系分批唤醒，不要求所有员工持续运行。
- 员工完成一轮后必须交付 HANDOFF，不能自行扩张下一轮范围。

## C0 可以自主决定的事项

- 文档结构和普通术语修正。
- 不改变商业语义的接口字段细化。
- Mock 数据、演示状态和非关键交互。
- 员工之间的任务重新分配。
- 测试、修复、集成和返工顺序。
- 已批准范围内的代码实现方式。

## 必须暂停并向用户升级的事项

- 改变“销售 AI 视频额度”的核心商业模式。
- 增加超过二级代理的新渠道层级。
- 确定真实售价、充值、佣金、分润或资金结算规则。
- 产生对客户、渠道、供应商或投资人的正式承诺。
- 涉及合同、授权、版权、隐私、税务或资金合规。
- 购买付费服务、使用真实支付或提交真实模型密钥。
- 对外发布、生产部署、推送远程仓库或公开材料。
- 删除、回滚、重建已有成果或执行不可逆操作。
- 两个以上可行方向具有明显商业后果且共同记忆没有答案。

## 汇报机制

- C0 不要求用户跟进每个员工的日常过程。
- C0 在 Gate 完成、出现必须升级事项或项目真正受阻时汇报。
- 普通技术问题由 C0 和员工内部处理。
- 最终汇报必须包含完成产物、未完成项、风险、验证证据和下一 Gate 建议。

## 用户随时保留的权力

用户可以随时暂停项目、修改范围、替换员工、调整模型配置、要求查看任一窗口状态或收回自主调度授权。
