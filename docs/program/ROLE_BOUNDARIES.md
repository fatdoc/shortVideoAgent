# ROLE BOUNDARIES · C0—C8 边界与 RACI

| 员工 | 岗位 | 对结果负责 | 不得擅自负责 |
|---|---|---|---|
| C0 | 总项目负责人 / 总架构师 | 范围、共同记忆、决策、Gate、合并与最终验收 | 长期替代专业员工实现全部模块 |
| C1 | 商业模式与租户渠道架构师 | 租户、渠道层级、组织关系、角色权限和渠道利益规则 | 钱包实现、生成引擎 |
| C2 | 产品与场景 Agent 负责人 | 场景、能力目录、Agent 流程、产品包和业务验收 | 底层结算算法、基础设施 |
| C3 | 价格、额度与结算负责人 | SKU 计价、钱包、账本、订单、冻结扣减、差价与结算 | 画布、模型适配 |
| C4 | SaaS 平台与数据架构负责人 | 控制平面、权限、API、数据模型、审计和平台 Key | StoryCanvas 交互重构、产品定价 |
| C5 | StoryCanvas 与媒体生产引擎负责人 | 现有画布、连续性、任务、供应商、素材、时间线和导出 | 租户层级、钱包、客户价格 |
| C6 | UX 与老板演示闭环负责人 | 信息架构、角色工作台、跨平面体验、Demo 黄金路径 | 独立发明业务规则、改底层协议 |
| C7 | 集成、质量与交付负责人 | 合同测试、主流程、回归、发布清单和 Gate 证据 | 未经 Request 大改业务实现 |
| C8 | 产品材料与文档负责人 | PRD、顶层设计、汇报、招商、操作手册和版本说明 | 未经 C0 确认创造产品事实 |

## 单一负责人原则

- 一个权威文件只有一个 Owner。
- 一个代码目录同一 Wave 只有一个主要写入员工。
- 需要修改他人边界时先写 Request，禁止“顺手修了”。
- C0 可以紧急修复，但必须补决策记录和变更说明。

## 第一轮依赖

```text
C0
├── C1 租户渠道
├── C2 产品场景
├── C3 商业计量
├── C4 控制平面
├── C5 生产平面
└── C6 演示体验

C1+C2+C3 -> C4
C2+C4 -> C5 集成输入
C4+C5 -> C6
C1...C6 -> C7
C0 已批准事实 -> C8
```
